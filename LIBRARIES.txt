Pulsekit native editions — libraries actually linked
====================================================

Proof is the jar metadata on disk plus the source line that loads it.
Hashes are SHA-256 of the jars in this workspace.

PLATFORM (not third-party jars)
-------------------------------
Desktop JAR
  JDK 17. Compile: javac --release 17, classpath adds JLayer and JNA.
  UI: javax.swing.* and java.awt.* imported by desktop/src/pulsekit/Pulsekit.java
  MIDI playback: javax.sound.midi.* from the JDK (Pulsekit.java lines 39–48).
  Entry: desktop/MANIFEST.MF  Main-Class: pulsekit.Pulsekit

Android APK
  Android SDK platform 33 (android.jar) at compile time, minSdk 24, targetSdk 33.
  android/AndroidManifest.xml
  Runtime UI/audio: android.* (MainActivity, AudioTrack via the activity).
  org.json is the platform class, not a Maven dependency.
  dalvik.system.DexClassLoader — ArtJava.java line 4.

NOT A LIBRARY
-------------
shared/src/pulsekit/midiutil.py is first-party. The header says
"MIDIUtil-compatible MIDI writer". It is not the MIDIUtil package.
It is copied into the desktop JAR and into the APK as assets/midiutil.py.

WHAT EACH EDITION SHIPS
-----------------------
Desktop JAR classpath / contents: Pulsekit classes + unpacked JLayer
  + unpacked JNA + drum_midi.py + midiutil.py. No ECJ, no dx, no rt.jar.
Android APK runtime: Pulsekit dex + assets
  (ecj.dex, dx.dex, ecj-res.zip, rt.jar, javax-midi.jar, MidiSystem.class,
   midiutil.py). No JLayer.
